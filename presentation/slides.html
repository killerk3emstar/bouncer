Bouncer

One checkpoint for every call an AI agent makes

A gateway between agents and models, MCP tool servers and other agents. One policy file. Deterministic checks first, a local AI judge only when needed. Every decision traced, budgeted and exportable. The checks run locally; no prompt is sent to a third party to be checked.

The problem: agents act, and nobody checks the action

Three public incidents from 2025. In each one the model did what the text told it to; the damage came from an action nobody inspected.

EchoLeak

Microsoft 365 Copilot · June 2025 · CVE-2025-32711, CVSS 9.3

One crafted e-mail. Copilot later reads it as context and puts internal data into a markdown image URL. The client fetches it: data gone, zero clicks.

nvd.nist.gov/vuln/detail/CVE-2025-32711

GitHub MCP hijack

Invariant Labs · May 2025

An issue in a public repo instructs the coding agent. It reads the owner's private repos and publishes their contents in a pull request on the public repo.

invariantlabs.ai/blog/mcp-github-vulnerability

postmark-mcp

npm · September 2025 · first malicious MCP server seen in the wild

Version 1.0.16 added one line: a hidden BCC to an attacker's address on every e-mail the agent sent. 1,643 downloads before removal.

theregister.com/2025/09/29/postmark_mcp_server_code_hijacked

Common pattern: untrusted input + access to sensitive data + a way to send it out (the "lethal trifecta"). You will not detect every injection. You can stop the action.

Where Bouncer sits, and how to connect

Agents change one line. Security owns one YAML file.

client = OpenAI(base_url="http://localhost:8700/v1", api_key="<agent key>")   # the only change in the agent

Four entry points: OpenAI-compatible proxy (plain and streaming) · MCP gateway /mcp · A2A gateway /a2a/<agent> · POST /v1/guard/check for anything else.

Controlling actions, not only text

  • Tool allowlists per agent, argument rules: mail only to bank.example, no BCC, transfer limits
  • Lethal trifecta: untrusted input + sensitive data + outbound tool in one session → a human approves
  • Goal alignment (T2): does this tool call serve what the user asked?
  • MCP pinning: definitions hashed; a changed tool ("rug pull") is blocked until re-approved
  • Budgets and loops: USD per team per day, per session, tokens per minute, GPU seconds, step limits, downgrade to a local model
  • Measured: injection missed, hijacked agent acts: 64/64 harmful calls stopped; injections wrapped to fool the judge: 0/64 actions got through

Policy as code, changed while it runs

profile: balanced        # permissive | balanced | strict
defaults:
  mode: enforce          # monitor = record, never block
  fail_mode: closed      # check errors or times out: block

controls:
  tool_governance:
    lethal_trifecta:
      action: require_approval
    goal_alignment:
      apply_to: side_effect_tools
      block_above: 0.60   # P("misaligned") from T2
      approval_above: 0.45
    arguments:
      mail.send:
        to_domains_allow: [bank.example]
        forbid_fields: [bcc]   # postmark-mcp
        action: block
  • One file, policy/bouncer.yaml, validated by a strict schema (unknown keys rejected)
  • Save it: applied in about 1 s, no restart
  • Invalid file: rejected with line and column, the last good version stays active
  • Every version hashed, diffed and written to the audit log; 20 versions of history
  • Three profiles, per-agent overrides, monitor mode for a shadow rollout
  • Judge thresholds are probabilities, so "adherence %" is a number in the policy
  • A removed control shows as disabled and the OWASP posture score drops (78 → 72)

Run it yourself

git clone https://github.com/killerk3emstar/bouncer
cd bouncer
make setup    # uv sync, .env from .env.example
make test     # 1231 tests, offline, ~12 s
make dev      # gateway, mock API, MCP, feed, A2A agent
make demo     # 12 attack scenarios, pass/fail table

Optional real models on Apple Silicon: make models, make judge. Also docker compose, with a CPU judge profile for other machines.

Scaling

  • Stateless gateway; with BOUNCER_STORE=redis:// replicas share spend, sessions and approvals (tested with two)
  • Judge is a separate service with one interface; swap the backend per hardware

Known limits

  • T1 reads English only; other languages go to the slower judge
  • A2A: no end-to-end signing, no streaming
  • Out of scope: hallucination (LLM09), training-data poisoning

Next

  • A2A streaming; judge as a shared GPU service for many gateways; per-agent behavioral baseline
