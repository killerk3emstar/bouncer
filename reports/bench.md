# Bouncer gateway benchmark

Generated by `scripts/bench.py` on 2026-10-04 00:53:07 CEST (86.1 s wall time).

## Setup

- Hardware: Apple M4 Pro, 48 GB, macOS 27.0.1; Python 3.12.11, onnxruntime 1.30.0.
- Machine load average before / after: [4.35, 4.23, 4.47] / [5.22, 4.65, 4.61] (the Mac is shared with another project, so absolute numbers carry noise).
- Gateway: `python -m bouncer.gateway.app`, one uvicorn worker, policy = `policy/bouncer.yaml` with upstreams pointed at the mock, judge backend `fake` (in-process, no model), team budgets raised so they never trigger, hot reload off.
- T1: `onnx` (protectai/deberta-v3-base-prompt-injection-v2, ONNX fp32 on CPU).
- T2: the fake judge answers in-process, so the `t2` column is near zero. Real judge latency is measured separately (`judge/bench.py`, `reports/judge_bench_*.json`).
- Upstream: `demo/mock_upstream.py` (simulated OpenAI API, no model) on the same machine.
- Client: a minimal asyncio HTTP/1.1 keep-alive client in one process (httpx on the client side became the bottleneck at 32 concurrent requests). Latency scenarios: 200 measured requests each after 10 warm-up requests, direct and gateway requests alternate. Every prompt is unique unless noted, so the T1 cache does not hide classifier cost.
- Gateway resident memory after the run: 1589.5 MB.

## What dominates the overhead

- `benign_short`: gateway overhead p50 8.7 ms, of which T1 8.2 ms (94%) and T0 0.3 ms; the rest (0.2 ms) is request parsing, policy lookup, audit write and proxying.
- `prompt_2kb`: gateway overhead p50 85.7 ms, of which T1 80.5 ms (94%) and T0 2.9 ms; the rest (2.3 ms) is request parsing, policy lookup, audit write and proxying.
- `benign_repeat`: gateway overhead p50 0.2 ms, of which T1 0.0 ms (0%) and T0 0.1 ms; the rest (0.1 ms) is request parsing, policy lookup, audit write and proxying.
- `secret_redaction`: gateway overhead p50 23.5 ms, of which T1 22.7 ms (96%) and T0 0.5 ms; the rest (0.4 ms) is request parsing, policy lookup, audit write and proxying.
- `tool_call_side_effect`: gateway overhead p50 10.3 ms, of which T1 8.8 ms (86%) and T0 0.3 ms; the rest (1.2 ms) is request parsing, policy lookup, audit write and proxying.
- `streaming`: time to first content chunk p50 0.3 ms direct vs 11.5 ms through the gateway. T1 on the prompt accounts for 8.3 ms of that (it runs before the request is forwarded); the rest includes the small window of text the gateway holds back so a secret split across chunks can still be redacted. Output scanning of the stream shows up as T0 (6.3 ms p50 over the whole stream).
- Throughput peaked at 102.2 req/s with 8 concurrent clients (single uvicorn worker, T1 onnx); p95 at that level was 80.7 ms.
- T1 p50 grows from 9.0 ms at 1 client to 316.6 ms at 32 clients. The ONNX classifier runs one inference at a time (one session behind a lock in `bouncer/t1/classifier.py`), so requests queue for it and throughput is capped near 1000 / T1 time = 111 req/s for short prompts. Without T1 the same path costs well under 1 ms (see `benign_repeat`, where the T1 result is cached).
- `secret_redaction`: 134 of 200 requests were escalated to the judge (t1_grey_zone 134). With the real judge each escalation adds the judge's latency (measured separately: `judge/bench.py`, `reports/judge_bench_*.json`, and `latency_ms_p50` in the judge's `GET /health`).
- With T1 disabled the same gateway serves 626.3 req/s (concurrent clients: 8, p95 15.0 ms); everything except T1 costs 0.3 ms p50 per request inside the gateway (audit `gateway_overhead`).
- Without T1, the next limit is the single worker process: the gateway's own `upstream` time grows from 0.5 ms p50 (concurrent clients: 1) to 34.7 ms (concurrent clients: 32) while the mock answers direct requests at the same concurrency in 2.2 ms p50. Gateway CPU per request rises from 1.26 ms to 2.23 ms over the same range, so the single worker saturates one core and the waiting shows up inside the upstream call, where the coroutine yields. The httpx client used for the upstream call degrades the same way under concurrency on the load-generator side (see the RawHTTP note in `scripts/bench.py`). More uvicorn workers or replicas scale this part; budget counters are the only shared state.

## Reproduce

```
make bench                                  # full run
uv run python scripts/bench.py --quick      # about 20-30 s
uv run python scripts/bench.py --t1 fake    # without the ONNX classifier
```

Ports 8705 (gateway) and 8706 (mock) by default; change with `--gateway-port` / `--mock-port`. Raw numbers: `reports/bench.json`.
